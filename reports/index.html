BEYOND ONE DATASET

Your schema.
The same foundations.

Checks use declared roles, not hard-coded column names. Bring CSV, JSON or JSONL and describe the contract the data must satisfy.

Make the rules explicit

{
  "columns": {
    "order_id": {"type": "string"},
    "amount": {"type": "number"},
    "placed_at": {"type": "datetime"},
    "shipped_at": {
      "type": "datetime", "nullable": true
    }
  },
  "primary_key": "order_id",
  "chronological_pair": [
    "placed_at", "shipped_at"
  ]
}
Open full example contract

What transfers

  • Required columns, nullability and explicit types
  • Primary keys and duplicate groups
  • Date formats and chronology
  • Coordinate ranges for any region
  • Categories and allowed value pairs
  • Text PII patterns and baseline null drift

What needs domain knowledge

Whether a complaint description makes sense, a number is commercially plausible, or a name is sensitive. Declare mappings or add domain validators; generic checks cannot prove universal correctness.
